# Engine

Pure, React-free versions of the scorecard's arithmetic. Nothing in here may
import from `react` or touch the DOM, so it can be tested directly.

## Why this exists

The grid is the thing everything else is derived from, and until now its
arithmetic lived inside a React hook where it could not be tested. Any change to
it silently rewrites every saved scorecard. These modules plus their golden-master
fixtures make that arithmetic pinned down and checkable.

## Files

| File | What it is |
| --- | --- |
| `grid.js` | The grid arithmetic, extracted from `useScorecardLogic.js` |
| `predict.js` | The prediction rules, shared by the main view and stealth mode |
| `analytics.js` | Pattern detection over the number columns |
| `grid.test.js` | Golden-master tests plus documented behaviour |
| `predict.test.js` | Characterisation tests for the prediction rules |
| `__fixtures__/golden-master.json` | 49 frozen grids, 61,136 cells |

Each of these had a second copy living somewhere else before it moved here, and
in both cases the copy had gone stale: stealth mode's prediction logic was
missing the Rule of Three, and a test helper's copy of the analytics matcher
missed the tie handling. If you find yourself about to duplicate one of these,
don't.

## How the golden master works

The fixtures were **generated by the original pre-extraction code**, not by
`grid.js`. `scripts/generate-grid-fixtures.js` holds a verbatim copy of
`calculateSingleRow` as it was at commit `301f190`, so the tests compare the new
module against an independent copy of the old one rather than against itself.

Rows are stored as comma-joined `displayValue` strings. That works because
`value` is always recoverable from `displayValue` plus the column index — the
generator counts any cell that breaks that rule, and the count is currently zero
across all 61,136 cells. The test re-derives and checks `value` separately, so
both fields are covered.

## When a golden-master test fails

It means the grid arithmetic changed. That is not automatically a bug, but it is
never a detail: every scorecard the user has saved will render differently, and
their own reading of the board will be off. Treat it as a deliberate decision,
not something to paper over.

To change the arithmetic on purpose:

1. Make the change.
2. Check which cases changed and confirm each is what you intended.
3. Regenerate with `npm run fixtures:grid` — but note the generator holds a copy
   of the *original* logic, so if you are genuinely redefining the arithmetic you
   must update that copy too, and say so in the commit.

## Ties

A tie takes a row of its own, marked `T` in the S column, so hand numbers stay
truthful and shoe depth stays recoverable. It is not a result:

- it does not count as a repeat or a switch, so it never changes an R/O marker;
- it carries no counts of its own, and the next hand continues from the row
  above it (`calculateSingleRow` takes a `parentRowIdx` for exactly this);
- `computeHighlights` leaves tie rows out of the column entirely, so a tie
  cannot split a pattern;
- `predictNextHand` anchors to the most recent decided row, so a tie cannot
  break the Rule of Three or shift a prediction.

The net effect is that a card with ties produces numerically identical rows to
the same hands with the ties removed. There is a test for precisely that.

Because a tie is stored in a cell that already existed, old saved scorecards
load unchanged and need no migration.

## Verified properties

Established while extracting this, with the evidence in each case:

- **Every number column moves in lockstep.** The row-to-row step is identical in
  every live column; they differ only by a constant offset. 27,200/27,200 row
  transitions.
- **A column dies permanently at ±4** and never recovers.
- **`pattern-343` can never match**, because a 4 is always followed by an X.
  Zero matches in 28,000 hands.
- **The `col === 3` seeding branch is dead code** — the 1/-1 backfill already
  covers it. 4,000/4,000 sequences identical with the branch removed.

## Mutation testing

The fixtures were checked by deliberately breaking the engine. Three of four
mutations were caught (threshold change, step sign flip, off-by-one on the X
check); the fourth turned out to be the dead branch above. Worth repeating if you
add cases — a golden master nobody has tried to break is not yet a safety net.
